# Архитектура экосистемы Telegram-ботов

Этот документ предназначен для разработчиков и **ИИ-ассистентов** (Cursor, Copilot, ChatGPT, Claude, Gemini), чтобы поддерживать единый стиль и целостность проекта.

---

## Концепция проекта
Экосистема состоит из группы независимых ботов (от 5 до 15), которые выполняют цепочки связанных сценариев.

### Принципы разработки:
1. **Модульность:** Каждый бот изолирован в своей директории `bots/bot_name/`. 
2. **Общий контекст данных:** Боты не дублируют базу данных — они используют общий модуль `shared/db` и общие модели.
3. **Межботовое взаимодействие (Inter-bot communication):**
   - Боты могут передавать пользователя друг другу через Deep Linking (например, `t.me/BotB?start=payload_from_BotA`).
   - Боты обмениваются событиями через общую БД или шину сообщений (Redis Pub/Sub / Queue).
4. **Безопасность:**
   - Никаких захардкоженных токенов и секретов в коде. Все токены берутся из `os.environ` / `.env`.

---

## Правила для ИИ-ассистентов
При создании или редактировании кода ботов:
- Создавайте обработчики в папке соответствующего бота (`bots/bot_xx/handlers/`).
- Не изменяйте структуру общих моделей (`shared/db/`) без согласования с командой через Pull Request.
- Всегда добавляйте обработку ошибок и логирование.
- Сохраняйте асинхронный стиль кода.
